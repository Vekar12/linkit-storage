01

What's changing and why

The current model requires each stage to be fully complete before the next one starts. This means teams wait idle even when the work they need to do is unrelated to what's blocking the previous stage. Document verification is repeated at multiple stages. The customer has no direct visibility into what's needed from them.

The new model breaks the journey into individual tasks. Each task is assigned to a stakeholder, has a clearly defined dependency, and appears in their tray only when it becomes actionable. Work that doesn't depend on each other runs in parallel.

Today
Sequential stages — one gate at a time
Entire stage blocked if one item pending
Document checklist repeated at 2 stages
Credit sees all docs only at DM Approval
Customer hears from Sales RM only
OTC/PDD manually classified by Ops
Docket Login is a separate gate
Proposed
Tasks with dependency logic — parallel by default
Only the dependent task is blocked
Per-document verification, once, continuously
Credit approves each doc as Ops clears it
Customer has a direct task tray
OTC/PDD driven by BRE (product/variant/state)
Docket Login eliminated — replaced by task-per-doc

Pain points

Sequential blocking

Any pending item at a stage gate blocks all other work, even unrelated tasks.

Duplicate checklist

34-point check runs at both Docket Login and DM Preparation.

Manual TSR handoff

TSR received by email, manually uploaded. No structured parsing — teams read the PDF.

Batched Credit review

Credit sees all documents only at DM Approval, even if individual docs could be approved earlier.

No customer visibility

Customer has no direct view of what's pending. Everything routed through Sales RM.

Manual OTC/PDD

OTC/PDD classification done manually by Ops; revalidated by Credit. No system-driven logic.

Proposed model – core concepts

Task dependency types

Every task belongs to one of three types:

TypeMeaningBehaviour
IndependentNo predecessorAppears in tray immediately on trigger
Semi-dependentOne predecessor must closeAppears only after that predecessor closes
DependentMultiple predecessors must all closeAppears only after all predecessors close
AutoSystem-triggeredNo human action needed to initiate

Stakeholder trays

Each stakeholder — Customer, Sales, Local Ops, Credit, RCU — has a tray: a personalised dashboard showing only tasks that are currently actionable for them. Pending tasks not yet unlocked are not shown. Completed tasks are archived.

DITM – Do It For Me

Sales RM can see and act on every task the customer sees. If the customer hasn't completed a task, Sales can complete it on their behalf. These are recorded as Completed by RM — distinguishable from customer self-serve.

Two document phases — completely separate

PhaseDocument typePurposeWhen
Legal & TechnicalScanned / uploaded copiesProperty verification, TSR generation, technical reportDuring Sourcing / Underwriting
Post Initiate DisbursementOriginal documentsSecurity creation, loan disbursementAfter Legal + Technical complete

OTC / PDD / Mandatory — document timing classification

Classification is BRE-driven (product + variant + state). Customers and Sales see all required documents as plain tasks — no OTC/PDD labels. If a document can't be submitted, Sales raises a Request OTC/PDD query which Credit validates.

TagMeaningGates
Mandatory / UpfrontCannot proceed without this document for this product/variant/stateBlocks further movement
OTCCollected at disbursement counter just before cheque is handed to customerGates cheque handover
PDDCollected before next tranche is releasedGates each subsequent tranche

Full stakeholder task summary

Customer
  • Upload scanned property documents for Legal initiation (BRE-driven list)
  • Upload additional documents if Legal vendor raises a query
  • Upload additional documents if Technical Admin raises a query
  • Submit original documents post Initiate Disbursement (BRE-driven list)
  • Fulfil sanction conditions (payment, closure proof, attested docs)
  • Review and accept Key Fact Statement
  • Complete E-Sign
Sales RM
  • Mirror of all customer tasks — can complete on behalf (marked "Completed by RM")
  • Initiate Legal (after mandatory uploaded docs ready)
  • Upload TSR to iLens (received from legal vendor via email)
  • Initiate Technical
  • Click Initiate Disbursement (after Legal + Technical closed)
  • Fill beneficiary, repayment, own contribution, EMI details
  • Raise OTC/PDD request if original document unavailable
  • Initiate E-Sign
  • Resolve all queries (from Local Ops, Credit, RCU) back to customer
Local Ops
  • Verify each original document via iLens checklist (per doc, continuously as docs arrive)
  • DM Preparation: page-by-page physical completeness check (parallel with data verification)
  • DM Preparation: cross-verify system data accuracy
  • Review own contribution; flag discrepancies
  • NDC Check via iLens NDC checklist (Credit Ops check merged in)
  • Submit case to Finone
Credit
  • Approve / reject OTC/PDD requests from Sales
  • Final document approval per doc — continuous as Local Ops clears each one
  • Revalidate sanction conditions
  • Verify original docs against TSR requirements
  • Verify TSR-flagged documents (Outcome C)
  • Validate pricing approval
  • Review and correct own contribution
RCU (Risk Unit)
  • FCBG: physically verify all original documents
  • Cross-check property registration on government websites
Technical Admin
  • Verify uploaded documents for technical initiation; raise query if insufficient
  • Allocate Technical Manager based on loan value
  • Validate technical report against Rapid system
  • Publish technical report to iLens
Technical Manager (Vendor)
  • Conduct physical site inspection — photographs, measurements, valuation
  • Submit draft technical report to Technical Admin
Legal Vendor
  • Review uploaded property documents (via iLens / email)
  • Raise queries for additional documents if needed
  • Generate TSR specifying original doc requirements and flags
  • Share TSR with Sales
System (Auto)
  • Generate BRE-driven document task lists for customer at each phase
  • Auto-trigger KFS when mandatory documents are Credit-approved
  • Auto-trigger eNACH alongside E-Sign
  • Generate e-signed booklet on E-Sign completion
  • Parse TSR and seed original doc tasks (List A) and Credit flags (List C)
  • Generate LAN on Initiate Disbursement
  • Auto-close dashboard tasks on iLens checklist completion

Glossary

BRE
Business Rule Engine — determines documents, checks, and classifications based on product, variant, and state.
CFF
Customer Finance Form — part of the e-signed disbursement booklet.
DITM
Do It For Me — Sales RM can complete any customer-facing task on behalf of the customer.
DM
Disbursement Memo — official memo with all loan and property details for disbursement approval.
DRF
Disbursement Request Form — part of the e-signed booklet.
FCBG / FCPG
Fraud Control check by RCU — verifies original documents and government property records.
iLens
ICICI Bank's internal mortgage processing platform — data entry, document upload, verification, and task management.
KFS
Key Fact Statement — regulatory document summarising loan terms; customer must acknowledge before disbursal.
LAN
Loan Application Number — unique identifier generated at Initiate Disbursement.
NDC
No Due Certificate check — final Local Ops verification before Finone submission.
OTC
Over the Counter — original document collected at disbursement counter just before cheque handover.
PDD
Post Disbursement Deposit — original document collected before next tranche is released.
POP Sheet
Part of the DM — lists all original documents from TSR with their collection status.
Rapid
Internal property rate and valuation dashboard used by Technical Admin to cross-verify reports.
RCU
Risk Containment Unit — responsible for FCBG verification.
TSR
Title Search Report — generated by legal vendor; specifies required originals, upload copies, and flags for bank verification.
Tray
A stakeholder's task dashboard — shows only currently actionable tasks.
