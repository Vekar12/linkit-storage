Overview & What's Changing

Today's disbursement runs on sequential stages with hard gates. One pending item in a stage holds everything — even work that has no dependency on it. The proposed model breaks everything into discrete tasks with explicit dependencies. Parallel work runs in parallel. Only genuine dependencies block progress.

❌ Current
✓ Proposed

Parallel tasks, only genuine dependencies block
Whole stage blocked if one item is pending
Only the specific dependent task is blocked
Stakeholder sees "stage in progress"
Stakeholder sees exactly what's in their tray
34-pt checklist repeated at Docket Login + DM Prep
Once per document, continuously, via iLens
Customer has no direct task visibility
Customer has their own live task tray
Credit reviews all docs in bulk at DM Approval
Credit approves each doc as Local Ops clears it
Docket Login as a separate stage
Eliminated — replaced by per-document tasks
OTC/PDD manually tagged by DM Prep team
BRE-driven classification, known upfront

2.3 Problems

  • Sequential blocking — one missing document holds the entire stage, even for unrelated work.
  • Duplicate checklist — 34-point check done twice with no additional value.
  • Manual TSR handoff — TSR received by email, manually uploaded; no structured parsing.
  • Bulk credit review — Credit sees all docs only at DM Approval, not as they arrive.
  • No customer visibility — all communication routed through Sales RM.
  • Manual OTC/PDD — classified manually instead of being BRE-driven.

4.3 Post Initiate Disbursement – Parallel Task Streams

Three pre-conditions must all be met before the Initiate Disbursement button is available to Sales. The button shows a checklist so Sales can see exactly which are pending:

#Pre-conditionHow it closes
1Legal closedT-L7 (System parses TSR) complete
2Technical closedT-T6 (Technical report published) complete
3Pricing Approval confirmedT-PRICE task in Sales tray — Sales confirms pricing approval from Credit hierarchy is in place
Property not identified at sanction? Sales gets a task in their tray — "Initiate Legal / Technical" — once property details are updated on the case. Same initiation flow, delayed trigger. On property change after Legal/Technical are complete, both workstreams fully restart for the new property and all downstream tasks from the old TSR are revised.

When clicked, LAN is generated and three streams fire simultaneously. The BRE already knows upfront which docs are Mandatory, OTC, and PDD. Sales collects all mandatory docs first, then submits as one batch. For any mandatory doc that Sales wants to mark as OTC/PDD, a Credit approval request is raised — the batch moves to Local Ops only after all mandatory docs are either physically collected or OTC/PDD-approved by Credit.

4.4 Document Verification Chain

Local Ops verifies each document independently within the batch — a query on one doc never holds others. If a doc fails Credit approval and is resubmitted, it goes back through Local Ops first, then Credit.

Quick reference — which tasks must close before something else unlocks.

When this completes……this unlocks

T-DOC1 batch submitted → T-DOC2.x (Local Ops verify) appears per document independently
T-DOC2.x verified (per doc) → T-DOC3.x (Credit approval) for that specific doc
T-DOC3.q.x — doc resubmitted after Credit query → T-DOC2.x re-triggered for that doc (Local Ops verifies again first, then Credit)
All mandatory Stream A + B + C tasks closed → DM Preparation tasks unlock for Local Ops (T-DMP1 + T-DMP2 in parallel)
T-DMP2 repayment details verified by Local Ops → T-ENACH eNACH auto-triggered by system

Glossary

BREBusiness Rule Engine — determines doc lists, checks, and classifications from product + variant + state.
CFFCustomer Finance Form — part of the e-signed disbursement booklet.
DITMDo It For Me — Sales can complete any customer task on their behalf; recorded as "Completed by RM".
DMDisbursement Memo — official memo with all loan + property details required for disbursal approval.
DRFDisbursement Request Form — part of the e-signed booklet.
FCBGFraud Control & Business Governance check by RCU. Verifies originals + govt property records.
IGFInitiate Go-Forward — first disbursement step in current model. Replaced by Initiate Disbursement in new model.
iLensICICI Bank's internal mortgage platform — data entry, doc upload, verification, and task management.
KFSKey Fact Statement — regulatory doc summarising loan terms; customer acknowledges before disbursal.
LANLoan Application Number — unique loan ID generated at Initiate Disbursement.
NDCNo Due Certificate check — final Local Ops verification via iLens checklist before Finone submission.
OTCOver the Counter — original doc collected just before cheque is handed to customer. Gates cheque handover.
PDDPost Disbursement Deposit — original doc collected before next tranche is released.
POP SheetLists all original docs required per TSR with collection status. Auto-populated from Stream A in new model.
RapidICICI's internal property rate & valuation dashboard used by Technical Admin.
RCURisk Containment Unit — responsible for FCBG verification.
TSRTitle Search Report — by Legal vendor; specifies original doc requirements and verification flags.
TrayStakeholder's personalised dashboard — only shows currently actionable tasks.
