Overview & What's Changing

The current disbursement process on iLens is stage-gated and sequential. Each stage must finish before the next one starts. This means teams wait idle even when they could be doing independent work.

The proposed model replaces stages with tasks. Every unit of work is broken down, assigned to a stakeholder, and given a dependency rule. Tasks that don't depend on each other run in parallel. The result: faster turnaround, no unnecessary blocking, and full visibility for every participant.

2.3 Problems with the Current Model

  • Sequential blocking — one missing document holds the entire stage, even for unrelated work.
  • Duplicate checklists — 34-point checklist done at Docket Login and DM Prep with no additional value.
  • Manual TSR handoff — TSR received by email, manually uploaded; no structured parsing of its content.
  • Bulk credit review — Credit sees all docs only at DM Approval, not as they arrive.
  • No customer visibility — customer has no direct view; all communication routed through Sales RM.
  • Manual OTC/PDD — classification done manually each time instead of being BRE-driven.
03

Proposed Model – Core Concepts

3.1 Task Dependency Types

Every task has one of three dependency types:

TypeMeaningBehaviour
IndependentNo predecessorAppears in tray immediately on trigger
Semi-dependentOne predecessor must closeAppears only after that predecessor closes
DependentMultiple predecessors must all closeAppears only when all predecessors are done

3.2 Stakeholder Trays

Each stakeholder — Customer, Sales, Local Ops, Credit, RCU — has a tray: a personalised view showing only tasks currently actionable for them. Tasks not yet unblocked are hidden. Completed tasks are archived.

DITM (Do It For Me) Sales can see and act on every task the customer sees. If a customer hasn't completed a task, Sales can do it on their behalf. These are recorded as Completed by RM — distinguishable from customer self-serve.

3.3 Document Phases & Timing Tags

PhaseDocument TypePurposeWhen
Legal & TechnicalScanned / uploaded copiesProperty verification, TSR, technical reportDuring Underwriting
Post Initiate DisbursementOriginal documentsSecurity creation, loan disbursalAfter Legal + Technical close

Originals are classified by the BRE (Business Rule Engine) based on product + variant + state:

TagMeaningGates
Mandatory / UpfrontCannot proceed without this document for this product/variant/stateBlocks further movement
OTCCollected at the counter just before cheque is handed to customerGates cheque handover
PDDCollected before the next tranche is releasedGates each subsequent tranche
Customer and Sales see all required documents as a flat task list — no OTC/PDD labels shown. If a document can't be submitted, Sales raises a Request OTC/PDD query. Credit validates and approves or rejects it.

Documents are submitted in batches (4–5 at a time). Each document is verified independently — a query on one document never holds others. The chain runs continuously and in parallel with all other work from the moment documents start arriving.

Stakeholder Task Summary

CUSTOMER
  • Upload scanned property docs (BRE list) for Legal
  • Upload additional docs if Legal vendor queries
  • Upload additional docs if Technical Admin queries
  • Submit original documents post Initiate Disbursement
  • Fulfil sanction conditions (payment, closure NOC, etc.)
  • Review and accept KFS
  • Complete E-Sign
SALES RM
  • Mirror of all customer tasks (DITM)
  • Initiate Legal + Initiate Technical
  • Upload TSR to iLens
  • Click Initiate Disbursement
  • Fill beneficiary, repayment, own contribution, EMI details
  • Raise OTC/PDD request if doc unavailable
  • Initiate E-Sign
  • Resolve all queries back to customer
LOCAL OPS
  • Verify each original doc via iLens (per doc, continuous)
  • DM Prep: page-by-page physical completeness check
  • DM Prep: cross-verify system data accuracy (parallel)
  • DM Prep: flag own contribution discrepancies
  • NDC Check via iLens (Credit Ops check merged in)
  • Submit case to Finone
CREDIT
  • Approve/reject OTC/PDD requests
  • Final doc approval per document (continuous)
  • Revalidate sanction conditions
  • Verify originals vs TSR
  • Verify TSR-flagged docs (List C)
  • Validate pricing approval
  • Review and correct own contribution
RCU
  • FCBG: physically verify all original documents
  • Cross-check property registration on govt websites
TECHNICAL ADMIN
  • Verify uploaded docs for technical initiation
  • Raise query if docs insufficient
  • Allocate Technical Manager (based on loan value)
  • Validate technical report against Rapid system
  • Publish technical report to iLens
LEGAL VENDOR
  • Review uploaded property docs
  • Raise queries for missing documents
  • Generate TSR with original doc requirements and flags
  • Share TSR with Sales (Sales uploads to iLens)
SYSTEM (AUTO)
  • Generate BRE-driven doc task lists for customer
  • Auto-trigger KFS when mandatory docs are Credit-approved
  • Auto-trigger eNACH alongside E-Sign
  • Generate e-signed booklet on E-Sign completion
  • Parse TSR → seed List A (original doc tasks) + List C (Credit flags)
  • Generate LAN on Initiate Disbursement
  • Auto-close dashboard tasks on iLens checklist completion

Glossary

BREBusiness Rule Engine – determines doc lists, checks, and classifications from product + variant + state.
CFFCustomer Finance Form – part of the e-signed disbursement booklet.
DITMDo It For Me – Sales can complete any customer task on their behalf; recorded as "Completed by RM".
DMDisbursement Memo – official memo with all loan + property details required for approval.
DRFDisbursement Request Form – part of the e-signed booklet.
FCBGFraud Control & Business Governance check by RCU. Verifies originals + govt property records.
IGFInitiate Go-Forward – first disbursement step in current model. Replaced by Initiate Disbursement in new model.
iLensICICI Bank's internal mortgage platform for data entry, doc upload, verification, and task management.
KFSKey Fact Statement – regulatory doc summarising loan terms; customer acknowledges before disbursal.
LANLoan Application Number – unique loan ID generated at Initiate Disbursement.
NDCNo Due Certificate check – final Local Ops verification using iLens checklist before Finone submission.
OTCOver the Counter – original doc collected just before cheque is handed to customer. Gates cheque handover.
PDDPost Disbursement Deposit – original doc collected before next tranche is released.
POP SheetPart of the DM; lists all original docs required per TSR with collection status.
RapidICICI's internal property rate & valuation dashboard used by Technical Admin.
RCURisk Containment Unit – responsible for FCBG verification.
TSRTitle Search Report – generated by Legal vendor; specifies original doc requirements and verification flags.
TrayA stakeholder's personalised dashboard showing only their currently actionable tasks.
