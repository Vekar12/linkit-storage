Mortgage Disbursement: Task-Based System

1. Current Process (Simplified)

  • Sequential flow: one step after another
  • Multiple teams check same documents repeatedly
  • Low visibility: unclear where case is stuck
  • Heavy dependency on sales for communication

2. Proposed System

  • No stages, only tasks
  • Tasks assigned to stakeholders
  • Parallel execution wherever possible
  • Clear: who needs to act and what is pending

3. Task Types

  • Independent: starts immediately (e.g. upload doc)
  • Semi-dependent: needs one trigger (e.g. verify after upload)
  • Dependent: needs multiple tasks done

4. Dashboard (Customer + Sales)

  • All tasks shown in one list
  • No separation like legal/technical
  • Only "what needs to be done"
Example tasks:
- Submit Agreement
- Pay Processing Fee
- Fill Beneficiary Details

5. Single Document Flow

Customer/Sales → Submit ↓ Local Ops → Verify ↓ Credit → Final Check
  • If issue → goes back to Customer/Sales
  • Each document moves independently

6. Parallel Example

Doc A → With Ops Doc B → With Customer Doc C → With Credit

All running at the same time.

7. OTC / PDD Logic

  • All documents start as mandatory
  • If not available → Sales raises request
OTC → must be collected before cheque handover
PDD → must be collected before next tranche
  • System suggests → Credit decides

8. After Document Completion

Docs Done → KFS → E-Sign → RCU Check → Ops Final Check → Submit
  • KFS → Customer accepts
  • E-sign → Sales initiates, Customer completes
  • RCU → verifies documents externally
  • Ops → final checklist
  • Submit → moves to Finnone

9. Key Rules

  • Each task has one owner
  • Tasks move based on completion, not stages
  • Queries affect only that task, not full case
  • System shows clearly: what is pending and with whom

10. Summary

System = task tracker + flow controller
Teams = execution
Goal = faster, clearer, parallel processing
