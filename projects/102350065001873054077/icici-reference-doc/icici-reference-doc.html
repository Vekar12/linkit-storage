1. Home Loan Disbursement Journey Optimization

  • Executed a two-stage removal in the HL disbursement journey — eliminated the Docket Login stage and the FinOne Maker stage — streamlining the disbursement workflow.
  • Introduced Partial eSign functionality for all users wherever eSign fails, enabling completion of signing for applicable sections without requiring a full re-attempt.
  • Onboarded an additional eSign vendor specifically for NRI customers (currently in deployment pipeline) to improve coverage for NRI cases.
  • Enabled eSign deactivation access for all sales users, removing dependency on backend/tech teams for case-level interventions.
  • Impact: eSign completion rate improved by 6% across the HL journey.

2. HL Disbursement Module — Automation & Manual Field Elimination

  • Identified and removed redundant manual input fields across the disbursement module (module ownership).
  • Introduced automation for data population where manual entry was previously required.
  • Impact: Achieved a 20% reduction in manual touchpoints; TAT reduced by X%.

3. Operational Checklist Optimization

  • Reduced the number of manual checks required in the operational checklist by Y%.
  • Impact: Saved approximately 20 minutes per operation per user, freeing operational bandwidth at scale.

4. Post-Disbursement Insurance Journey (Built End-to-End)

  • Designed and built an insurance journey within iLens, triggered post-loan-disbursement.
  • Sales users can select the insurance partner, fill in required details, and submit — the request flows directly to the customer's Track My Application (TMA) for consent and approval.
  • Upon TMA approval, the insurance booklet is generated and consumed at the insurance partner's end.
  • Replaced an entirely physical/offline process with a digital workflow.
  • Introduced self-funded vs. bank-funded logic:
    • Premium < INR 25,000 → automatically routed as self-funded.
    • Premium > INR 25,000 → bank-funded option provided, with TMA consent from the customer.

5. Insurance Lead Capture in Parent HL Sourcing Journey

  • Built functionality within the parent Home Loan journey to capture insurance intent at the initial sourcing stage itself.
  • A task is created in the customer's worklist where they can select from available insurance partner options.
  • The selected lead is captured and delivered to the insurance partner.
  • Post-disbursement, the case status is automatically updated, and the customer is contacted by the partner for initial screening.
  • Impact: Created an integrated, end-to-end insurance funnel embedded within the loan lifecycle.

6. Customer-Facing Disbursement Journey (Information Gathering Form)

  • Identified a critical gap: customers were unaware of the documents required in original format before initiating disbursement. Information was exchanged via WhatsApp/email through sales users and manually entered — leading to delays, errors, and poor customer experience.
  • Built a customer-initiated disbursement flow on Track My Application (TMA):
    • Post-sanction, customers can initiate disbursement directly.
    • An Information Gathering Form (IGF) screen displays all required documents, account details for debit, and disbursement amount — before submission.
  • Impact: Established transparency in the disbursement process, eliminated manual relay through sales, and empowered customers to prepare documents proactively.

7. Bulk Upload for Login Fees Knockoff (Pan-India Process Elimination)

  • Eliminated the per-case manual knockoff process for login fees that was followed across all of India.
  • Developed a bulk upload functionality in FinOne: the Razorpay team publishes an MIS, a single user uploads it into FinOne, and knockoff is applied to all applicable cases automatically.
  • Impact: Replaced a repetitive, case-by-case manual process with a single bulk operation, significantly reducing operational effort Pan-India.

8. Query Management Overhaul — Knowledge Byte Initiative

  • Identified that escalations and queries were being handled directly by the product/front-end team, causing a severe bandwidth bottleneck.
  • Raised a requirement and established a dedicated query-handling team (vServ) with a single contact number for all sales/operations queries.
  • Introduced two in-system tools:
    • Ticketing Tool: On encountering a technical error, users press the ticketing button — a screenshot is auto-generated, they describe the issue, and a ticket is raised. TAT reduced from 4 hours to 2 hours.
    • Chatbot: A Python script-based chatbot pre-loaded with frequent/process-related queries. Uses a 75% term-match threshold to suggest relevant answers and options. (Deterministic script with curated Q&A, not an AI model.)
  • Impact: Deflected a significant volume of queries away from the core team, improved resolution speed, and created a self-service layer.

9. System Performance — iLens Data Archival

  • The iLens application (5+ years old) had every historical application active in the main database, causing significant system load.
  • Average search time for one HL application: 7–10 seconds.
  • Executed a data archival strategy: all cases older than 2 years were archived out of the main database.
  • Archived data stored in the DWH (Data Warehouse) server; year-wise zip files created and stored on the server with access provided to iLens users for extraction.
  • Impact: Application search time reduced from 7–10 seconds to ~1.8 seconds.

10. eNACH Module — NLI Page Removal

  • Identified 4 latency lags in the eNACH module's flow to reach final banking details.
  • Removed the NLI intermediary page that sat between TMA and the bank's portal (previously, the flow went TMA → NLI page → vendor page → bank portal).
  • Enabled direct redirection from TMA (after consent) to the corresponding bank's ID.
  • Impact: Eliminated a failure point that made identifying and pinpointing where cases were stuck extremely difficult, enabling faster debugging and resolution.

11. Education Loan — Receipt ID Creation API (Login Fees Automation)

  • Built a Receipt ID Creation API that completely terminated the manual login fees check module from the operations user's worklist.
  • New flow:
    • Payment enabled directly from iLens — a task is created in the customer's worklist, or the sales user generates a QR from iLens.
    • Customer pays via UPI, credit card, or other modes (powered by Razorpay).
    • The API posts the Payment ID along with the EL application number directly into FinOne Neo.
    • FinOne Neo marks the payment as received.
    • Upon loan account number (LAN) generation, the EL reference number is linked to the LAN, and the payment is marked as settled.
  • Previously, operations had to manually wait for Razorpay's payment ID to convert to a receipt with UTR + AXN number, then manually enter it into FinOne Neo — with no system integration between iLens and FinOne Neo.
  • Impact: Eliminated an entire manual reconciliation and entry process, drastically reducing operational bandwidth consumption.

12. Secure Data Sharing Automation (Insurance Partners)

  • Previously, iLens and FinOne data dumps were manually downloaded by individuals and shared via email to insurance companies — a significant data security and compliance risk (contained customer PII).
  • Redesigned the pipeline:
    • iLens data stored in the Data Warehouse (DWH).
    • FinOne data extracted via an automated scheduler (no manual download) and placed in a designated path.
    • AI Automation (ICICI's internal scheduler-based integration service) picks data from the source path and pushes it to an SFTP server.
    • SFTP access provided to ICICI Lombard directly.
    • For ICICI Prudential, built a workaround: a linear script on the SFTP admin triggers an automatic push to Prudential's SFTP whenever new data arrives.
  • Impact: Eliminated manual data handling, removed email-based sharing of sensitive customer data, and ensured compliance with data security protocols.

13. Auto Loan — eSign Journey Decoupling

  • At launch, the Auto Loan journey had eNACH, eSign, and Stamp Duty configured as a linear/sequential chain — failure in any one step caused the entire eSign to fail.
  • Additionally, 11 states (including Bihar, Haryana, Jharkhand) do not support e-stamping, requiring physical stamping only — which caused blanket failures in those regions.
  • Decoupled all three services into independent, parallel processes.
  • Impact: eSign completion rate increased from 46% to over 96% for the Auto Loan journey.

14. Master-Based Configuration for Incremental Changes

  • Identified that small UI/config changes (e.g., checklist updates) required the product team to raise a requirement, go through a development cycle, and deploy — taking up to 1 month.
  • Converted these to master-based configurations, handing ownership to the operations team.
  • Impact: Changes that previously took 1 month can now be executed in 1–2 minutes by operations directly, without any tech dependency.

15. OTP Reduction in Disbursement Journey

  • Audited the disbursement journey and found customers were prompted for OTPs 6–7 times on average.
  • Rationalized OTP triggers across the flow.
  • Impact: Reduced average OTP prompts from 6–7 to 3, improving customer experience and reducing drop-offs.
